# 용어집 (구↔신 통합)

grill 세션에서 합의된 언어. 화면·코드·문서에서 이 이름을 쓴다. ⚠️ = 아직 미확정.

| 용어 | 뜻 | 구에서의 옛 이름 | 비고 |
|---|---|---|---|
| 구 | agent 레포(ChaosPilot) 대시보드 | — | 흡수 원본 |
| 신 | chaoslab 대시보드 | — | 흡수 대상(허브) |
| 앱 (App) | 실험 대상 워크로드(SUT). 환경·소스 정보를 소유 | 프로젝트 | ADR-0001 |
| 환경 | 앱이 배포된 클러스터 종류: k3s(온프레미스) / EKS(클라우드) | 실행 대상(장식 토글) | 앱의 속성, 유저에게 안 물음 (ADR-0002) |
| 소스 | 앱을 만들 때 준 것. **환경이 결정**: k3s→manifest YAML, EKS→git 저장소 | 시작 방식(샘플/직접 업로드) | ADR-0003. Boutique는 등록 밖(인프라 소유) |
| ⚠️ 부하 검증 경로 | k6가 부하를 보내는 경로. 현재 `/healthz` 잠정 유지 — 기능 경로 승격 재논의 필수 | 헬스체크 경로 | ADR-0005 (알려진 설계 오류) |
| 설계 방식 | 실험을 만드는 방법: 직접 설계 / AI 추천 | (구는 AI만 존재) | 새 실험 위저드 step 2 |
| 후보 | AI가 제안한 실험안. 승인 전에는 실행되지 않음 | 실험 후보 | |
| 승인 게이트 | 유저가 후보를 골라 확정하는 단계 | 선택 확정 | 우리 워크플로우의 시그니처 |
| 검증 목표 | AI 후보 생성에 참고되는 유저의 자유 서술 | 검증 목표 textarea | |
| R 지수 | 회복탄력성 점수 = 0.4·가용성 + 0.3·레이턴시점수 + 0.3·복구속도 | (원시 지표만 저장) | 중간보고서 확정 수식 |
| ⚠️ 실험 묶음 | AI 모드에서 후보 여러 개 연쇄 실행+개선 반복을 묶는 단위 | 프로젝트의 chaos 단계 | 신 데이터 모델에 없음 — 백로그 |
| 가설 수립 | 실험의 첫 단계: 위저드 요청 → AI 후보 생성 → 승인 게이트(선택·직접 입력)까지 | AI 후보 생성 | ADR-0006·0010, 스펙 2026-08-25 |
