# ADR-0008: 실험 상세는 스테퍼 + 단일 스크롤, 판정은 체크리스트 전체 노출

- 날짜: 2026-08-04
- 상태: 승인 (시웅 결정, grill 세션)

## 결정

- **페이지 골격 = 스테퍼 + 단일 스크롤**: 상단에 실행→판정→개선→보고 진행 스테퍼,
  아래는 단계별 섹션이 순서대로 쌓이는 단일 스크롤. 실험이 "진행 중인 이야기"로 읽히게 한다.
  신의 기존 5탭(개요/메트릭/AI루프/개선/로그)은 폐기 — 탭 간 이동으로 진행 흐름이 끊기고,
  Istio·Grafana·LLM 비용·R 예측 등 구 현실과 안 맞는 요소가 많았음.
- **판정 표시 = 12종 체크리스트 전체 노출**: policy.py deterministic 체크를 통과/실패 아이콘과
  함께 전부 나열, 실패 항목은 관측값·기준값 근거 표시. "판정은 LLM이 아니라 관측값 기반"이라는
  신뢰성 포인트를 화면이 그대로 증명한다. smoke에서 취약 샘플이 정확히
  `ready_pods_maintained_during_fault` 1개만 False로 떨어진 사례가 대표 시나리오.
- **개선 루프 = iteration 카드 세로 나열**: iteration마다 패치 요약 + YAML diff(접힘) +
  안전 검증 결과 + 재실험 판정을 카드 하나로. smoke의 "replicas 2 + PDB → passed" 스토리가
  카드 한 장으로 읽힌다.
- **보고 = 마지막 섹션**: 원시 지표 before/after 비교 중심. R 지수는 수식 미확정이므로
  "원시 지표만 저장 · 수식 논의 중" 배지로 정직하게 표기 (없는 숫자 만들지 않음).

## 결과

- `experiment_detail.html` 전면 재작성. 데이터는 `_run_stub()` (pages.py) — 실배선 시
  구의 runner/policy/patch_agent 산출물로 대체.
- 상태 2종 시연 가능: running(실행 섹션 진행 중 + 이후 대기) / completed(실패→개선→통과 전체 스토리).
- NetworkChaos 실행 화면에는 ADR-0005 경고(/healthz 얕은 측정) 상시 표기.
- 계획 검토의 "실험 실행할게요" 버튼은 해당 앱의 최근 실험 상세로 이동(모의).
