# ADR-0006: 실험 설계는 AI 후보 선택형 — 직접 설계 폼은 제거한다

- 날짜: 2026-07-29
- 상태: 승인 (팀 기획 문서의 회의 합의 반영, grill 세션에서 확인)

## 맥락

팀 기획 문서 "Human-in-the-loop 구조"에서 두 방식을 검토했고 회의로 결론이 났다:
- 방식 1: 실험 전 사용자가 서비스 설명·원하는 장애 방향을 입력
- 방식 2: 에이전트가 시스템을 분석해 장애 테스트 후보군 생성 → 사용자가 후보 중 선택
- **합의: 방식 2로 간다. Claude Code처럼 선택지(1, 2, …)를 주고, 마지막 선택지는 사용자 자유 입력.**

한편 신(chaoslab)에는 태윤이 만든 수동 실험 폼(카오스 종류·파라미터 직접 입력)이 있었고,
2026-07-29 목업 위저드에서 "직접 설계 vs AI 추천" 공존 분기로 임시 보존했었다.

## 결정

- 새 실험 위저드에서 **"설계 방식" 선택 step을 제거**한다. 실험 설계는 항상 AI 후보 선택형.
- 위저드는 ① 대상 앱 → ② 검증 목표(선택)+고급 설정 → "후보 생성 요청"으로 축소.
- 후보 도착 화면은 Claude Code 패턴: **후보 카드 1..N + 마지막 선택지 "직접 입력"(자유 텍스트)**.
  자유 입력은 구조화된 폼이 아니라 자연어 서술이며, 에이전트가 이를 실행 계획으로 구체화한다.
- 태윤의 수동 폼 UI는 화면에서 사라지지만, 그 백엔드 로직(chaos_specs 검증·CRD 생성)은
  "선택된 후보/자유 입력 → 계획 구체화"의 내부 부품으로 재활용한다.

## 근거

- 사용자 주도권(Human-in-the-loop)은 별도 수동 모드가 아니라 **승인 게이트 안의 자유 입력**으로 보장 —
  단순 자동 실행이 아닌 사용자 승인 기반 흐름이라는 기획 원칙과 일치.
- 이전 임시 결정(공존, 직접이 기본)의 근거였던 "팀 합의 없는 삭제 부담"은 회의 합의 존재로 소멸.

## 결과

- 목업 단계: AI 루프 백엔드(Phase 3)가 없으므로 후보 화면은 stub 데이터로 시연.
- 실배선 전까지 실작동 경로(수동 실험)가 UI에서 사라지는 공백은 목업 목적상 수용.
