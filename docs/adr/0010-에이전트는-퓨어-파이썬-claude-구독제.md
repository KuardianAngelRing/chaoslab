# ADR-0010: LLM 에이전트는 LangGraph 대신 퓨어 Python + claude 구독제

- 날짜: 2026-08-25
- 상태: 승인 (시웅 결정, grill 세션)

## 맥락

중간보고서에는 "LLM 에이전트 = LangGraph 워크플로우형"으로 확정 기재돼 있었다.
가설 수립 단계(첫 에이전트 배선)를 시작하며 이 선택을 재검토했다.

## 결정

- **LangGraph를 쓰지 않는다.** 에이전트 루프는 퓨어 Python(대시보드의 백그라운드
  태스크·DB 상태 관리)으로 직접 짠다.
- LLM 호출은 **claude 구독제의 headless CLI(`claude -p`)** 를 subprocess로 호출한다.
  실행 전제는 "대시보드가 도는 호스트에 claude 로그인이 돼 있다"이다.
- 호출부는 기존 관례대로 **Protocol 뒤에 격리**(`HypothesisAgentService` 등,
  Stub/Real 전환은 `deps.py`) — 추후 API 직접 호출·타 프레임워크 전환은
  구현체 교체 문제로 남긴다.

## 근거

- **비용**: 팀이 이미 보유한 구독제로 호출당 추가 비용이 없다. API 종량제 대비
  지금 가장 싸고, 사용 가능한 모델 성능도 가장 좋다.
- **복잡도**: 우리 워크플로우의 상태(실험 단계·승인 게이트·반복 이력)는 이미
  대시보드 DB가 소유한다. 그래프 프레임워크가 얹어줄 상태 관리가 중복이고,
  학습·의존성 비용만 남는다. 워커·메시지큐 없는 단일 프로세스 구조(기존 확정)와도
  퓨어 Python이 더 맞다.

## 결과

- 중간보고서 기재와 달라진다 — 최종보고서에 반영하고 팀에 공유 필요.
- `handoff_schema.py`의 `Budget`(LLM 비용 USD 잔여) 필드는 구독제에서는 호출당
  비용이 0이라 의미가 약해진다 — 계약 개정은 백로그(반복 횟수 예산은 유효).
- EC2 등 원격 호스트 운영 시 구독 로그인 유지 방안은 미해결 — 필요 시점에 논의.
