# ADR-0003: 앱 등록의 첫 분기는 환경(k3s/EKS)이다

- 날짜: 2026-07-29
- 상태: 승인 (시웅 결정, grill 세션)

## 맥락

앱 등록 화면의 첫 질문 후보는 둘이었다:
- A. 소스 형태 먼저 — "git 저장소(빌드형) vs manifest YAML(완제품형)", 환경은 유도
- B. 환경 먼저 — "k3s vs EKS", 소스는 환경이 결정

개념적으로는 A가 더 일반적이다(같은 환경에 두 소스가 공존 가능). 그러나 이 프로젝트의 현실은
**k3s = manifest 업로드만, EKS = git 빌드 파이프라인만**으로 고정돼 있다.

## 결정

**B. 환경을 먼저 묻는다.** 환경 선택이 소스 입력 방식을 결정한다:
- k3s(온프레미스) → manifest YAML/ZIP 업로드 (구 ChaosPilot 방식)
- EKS(클라우드) → GitHub URL 등록 → 빌드·배포 (신 기존 방식)

## 유효 조건 (깨지면 재검토)

- "EKS = git 빌드형만"은 **등록 플로우의 스코프 선언**에 의존한다: Online Boutique(EKS+manifest 완제품)는
  등록 플로우 밖 — 인프라(up.sh/Iac-aws)가 배포·소유하며 대시보드 등록을 거치지 않는다.
- EKS에 manifest 완제품형 사용자 앱을 등록해야 하는 요구가 생기면 이 ADR을 재검토하고
  소스 분기(A)로 전환을 검토한다.

## 결과

- 등록 위저드 step 1 = 환경 선택. step 2+ = 환경별 소스 입력.
- App 도메인 모델에 환경 필드가 필수가 된다 (ADR-0002의 백로그와 합류).
- k3s 분기의 입력 최소셋: manifest 업로드 + namespace + healthcheck 경로(승격, k6 판정용).
  env_text·framework 등 구의 장식 필드는 계승하지 않는다.
