# ADR-0004: k3s 앱 등록은 배포까지 한 번에 간다

- 날짜: 2026-07-29
- 상태: 승인 (시웅 결정, grill 세션)

## 맥락

k3s(manifest 업로드형) 등록의 끝을 어디로 할지: 저장까지(A) / 배포까지(B) / 구처럼 분석까지(C).

## 결정

**B. 등록 버튼 하나가 저장+클러스터 apply까지 수행한다.**
- "배포 안 된 앱"이라는 어중간한 상태를 목록에 만들지 않는다.
- EKS 등록(등록=빌드+배포, building 상태 SSE)과 대칭 — k3s는 applying→healthy 상태를 같은 패턴으로 보여준다.
- CTA는 이중 동작을 정직하게: "등록하고 배포할게요".
- 전처리(인프라 분석)는 앱 준비가 아니라 실험의 시작 — 등록에 포함하지 않고 AI 추천 플로우 소속 (구의 C안 폐기).

## 네임스페이스

- namespace는 **앱 이름에서 자동 파생**(order-msa → ns `order-msa`), 수정은 고급 옵션에서만.
- 구의 "기준 네임스페이스: default" 입력은 계승하지 않는다 (공유 클러스터에서 나쁜 기본값).
- 앱↔네임스페이스 1:1이 공존 원칙 — 같은 클러스터에 다른 앱이 있어도 namespace가 다르면 충돌 없음.
- 구의 "실험마다 전용 namespace 격리"는 별개 주제(실험 실행 해체 시 다룸).
